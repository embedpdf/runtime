## Upstream changes outside the conflicts

- **Closed popups get no appearance (`4fa235012`).** Upstream's `ShouldGenerateAP()` now
  returns false for a closed popup, so building an annotation list writes nothing for it. That is
  the leak our reads-dont-write change fixed in `CreatePopupAnnot()` (the popup was made with
  `MissingAppearance::kGenerateWhenDrawn`). Ours is dropped; upstream's code does the same. The
  enum stays: `EPDF_RenderAnnotBitmap()`, `EPDF_RenderAnnotBitmapUnrotated()` and
  `EPDFAnnot_GetDrawingRect()` still use it. Upstream's new popup tests pass.
- **`CFX_RenderDevice::CreateForBitmap(bitmap, backdrop, rgb_byte_order)` (`e644f8cba`).** The byte
  order moved to the third argument, so our two-argument calls passed it as the backdrop. Ported
  in `EPDF_RenderPageBitmapWithMatrix_Start()`, `EPDF_RenderAnnotBitmap()` and
  `EPDF_RenderAnnotBitmapUnrotated()`, as upstream's own callers.
- **FreeType optional (`e72afa79f`).** `fxcrt` no longer passes FreeType's include path to every
  target. Our base and layer documents (in `parser`) make their page and render data, whose font
  headers need it, so `parser` now depends on `fxge` (tagged in `parser/BUILD.gn`; skipped with
  Skia, where upstream already adds it). Our builds keep FreeType; the fork's own font code
  (`GetFsTypeFlags()`, CID-keyed CFF, the font registry) needs it.
- **libyuv (`88d0b7025`, `c585d039f`).** On by default (`pdf_use_libyuv = true`): RGB byte
  swapping and BGR-to-BGRA compositing go through libyuv. A new dependency for every target, wasm
  included.
- **Rectangles with extra points (`321be12a4`, `97ab661d8`).** A rectangle path with a point in
  the middle of an edge is still a rectangle, and is written as `re` with the right corner. Only
  upstream's call sites write `re`.
- **Text page ignores non-finite objects (`06fbf69b3`)**, **old-style named destinations
  dereferenced (`e0dd7ca09`)**: no overlap with ours.
- **Stretch engine and 24-bit decode (`aeb3d6e3d`, `bd9ff698b`, `68b540df6`)** sit next to our
  render-speedup row loop and decoded-image-store code, without overlap.
