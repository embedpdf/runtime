## Upstream changes outside the conflicts

- **Shared objects found again (`a724e52c52`, `99da130a26`, `583f8062d0`):** the reference graph is
  built first, then counted, and cycles are found by depth-first search. The old check dropped
  valid edges as cycles, so a stream used twice (page content and an image, say) could count as
  unshared and be edited in place. Our page content generator uses these counts.
- **New annotations are indirect (`89660bafdb`):** `FPDFPage_CreateAnnot()` makes the new `/Annots`
  entry an indirect object (ISO 32000-1 table 30). `ConvertToIndirectObjectAt()` keeps our write
  guards; the engine creates annotations through our own functions.
- **192-bit AES rejected (`982029caf3`):** the standard has no AES-192; a file asking for it fails to
  load instead of reaching a CHECK when encrypting. Nothing of ours offers it.
- **`FPDFPage_GenerateContent()` ends an in-flight progressive render (`a6d2653579`).**
- **Decoder rewinds reset their state:** fax (`867e322d39`) and flate predictor (`0254d297c7`, our
  fix, see Conflicts).
- **Rendering:** `CheckSimpleLinePath()` float overflow (`4e04b1315d`), BGRA-to-mask compositing with
  Highway (`a5834506d0`), span wrappers for libyuv (`e24d49c9fa`; not on wasm32).
- **New tests that meet fork behaviour,** see Tests: `IsSupportedSubtype` (`7efd3f31d5`) and
  `ActualTextOnRtlGlyphsWithNumbersAndPunctuation` (`ddb2abb6fb`); `RtlMultiCharGlyph` (`40367e9219`)
  passes as upstream wrote it.
- Not in our builds: XFA and FormCalc (`1f02bc7d90`, `916d6f589a`, `e1f3a77c52`, `9a0f5b3e54`,
  `4a9b009526`, `ec80692828`, `fc08db6a73`, `e3fba831d9`, `d340036bb3` and its revert), V8 JavaScript
  tests, Highway's riscv config. Many new unit tests, all passing.
