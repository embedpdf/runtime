## Upstream changes outside the conflicts

- **Flatten prunes flattened fields (`3422572b1`).** `FPDFPage_Flatten()` now removes the page's
  widgets from `/AcroForm /Fields` (a widget another page still shows stays) and drops
  `/AcroForm` when no field is left. Layer mode caught two problems in the new code, both fixed
  in `fpdf_flatten.cpp` with tags:
  - it reads every page's `/Annots`, so `FPDFPage_Flatten()` now opens a page view (view-scope);
    without one, a page whose annotations the layer had copied up hit the view detector's
    `DCHECK`;
  - it read every field through mutable getters. On a layer that copies the field up, the copy
    matched no widget read from the page, so `/AcroForm` was kept, and every field of the form
    was copied into the layer. The walk now reads through const accessors and takes an array
    mutable only when an entry goes (reads-dont-write).

  Our own `EPDFPage_Flatten()` already detaches flattened widgets from the field tree and is
  unchanged.
- **Creation date with a time zone (`64f69426a`).** A new document's `/CreationDate` is
  `D:YYYYMMDDHHmmSS+HH'mm'`.
- **APIs ported into our code:**
  - `CFX_Color`: the constructors are private; use the factories (`6d6b8fa24`).
  - `CFX_StandardFont`: the base-14 tables and `kNumStandardFonts` (`64e7c4610`, `5e6d1de50`).
    The font mapper's base font is a `std::optional`; our built-in-face check uses
    `has_value()`.
  - `CFX_RenderDevice::CreateForBitmap()`: replaces `CFX_DefaultRenderDevice`, and can fail
    (`a6be8be9a`).
  - `CPVT_Word` accessors (`7053128ea`).
  - `pdfium::LineBreakType` (`4f41484a3`).
  - `CPDF_FaceBasedSimpleFont` (`91afa2051`).
- **`ByteStringPool::Clear()` put back.** Upstream removed it as unused (`fc8a4a63a`). Our save
  reader clears its own pool between objects, so a full rewrite of a large file doesn't keep
  every name it read. Re-added in `bytestring_pool.h`, tagged save-traversal.
- **Skia's `SkLog()`.** After the Skia roll (`282b9cff5`), Skia's assertions call `SkLog()`. Our
  geometry-only `redaction_pathops` target now builds `SkLog.cpp` and the platform's
  `SkLog_*.cpp`, as upstream's `:skia` target does.
- **New API:** `FPDFBookmark_GetColor()`.
