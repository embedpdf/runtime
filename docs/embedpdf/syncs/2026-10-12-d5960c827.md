## Upstream changes outside the conflicts

- **Page dictionaries (`dcc3dc6e7`, `3fe931553`, `d39027e3b`).** Upstream requires a page's
  `/Type` to be `/Page` or absent (`IsValidPageDictLoose()`) and makes it `/Page` by writing it:
  the constructor adds a missing one, and the page-tree walk (`GetNodeType()`) rewrites a missing
  or wrong one. Both are reads, and on a layer they write the frozen base. Ours: a page is any leaf
  of the page tree, `/Type /Page` or no `/Kids` and any `/Type` but `/Pages`
  (`CPDF_Document::IsPageTreeLeaf()`, which `GetNodeTypeForTraversal()` now uses too). That is
  the set upstream's walk turns into pages, checked without writing. It's the constructor's
  precondition, `IsPageObject()`'s check (the page-editing API), and every load we own:
  `NewPage()`, the page-size read, `EPDFPage_GetAnnotRaw()`, `EPDFPage_CreateAnnotRaw()`, the
  redaction mark sanitizer. A dictionary that fails it fails the call instead of hitting the
  constructor's `CHECK`. `FPDFPPOEmbedderTest.ImportIntoDocWithWrongPageType` (a `/Type /Template`
  page) loads as before.
- **Name-tree limits (`df3e2a600`).** Its title says lookups no longer truncate `/Limits`, but
  the condition truncates on exactly the lookup path; worth reporting upstream. Lookups also
  reordered reversed limits in place. Ours: a lookup reads the limits in order and writes
  nothing (write audit below).
- **Loose character box (`2558d5d97`).** Ascent and descent are now bounded by `/FontBBox`;
  `GetCharLocalBoxes()` follows (rule text-geometry).
- **Test fixture (`7a847da65`, `e1decb6e4`).** Upstream added a second, kerned line and an
  embedded font to `vertical_text.pdf`. Our five tests on it (vertical redaction, char geometry)
  now open `embedpdf_vertical_text.pdf`, the fixture as it was before; two had started failing.
- **New API.** `FPDFText_SetPositions()` (experimental); `FPDFPage_InsertObject()` now returns
  `FPDF_BOOL`. Both reach the engine's generated bindings at the next runtime build.
