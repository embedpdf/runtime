## Upstream changes outside the conflicts

- **No more "standard" CMYK conversion (`2b52a82ab`).** Images drawn with a soft mask or a
  non-normal blend mode converted DeviceCMYK with `1 - min(1, C + K)`; they now use the same CMYK
  conversion as everything else, which upstream says matches other renderers (its corpus test
  `bug_557320961` changed). Such images render a little differently; engine render expectations
  with CMYK images under soft masks or blend modes may move when the engine adopts this runtime.
  The `bStdCS` / `std_cs_` plumbing is gone, so:
  - our decoded image store (`cpdf_decodedimagestore.*`, decoded-image-store) no longer keys on
    `std_cs`; the conversion no longer depends on it;
  - `cpdf_pageimagecache.cpp` and the image redactor (`cpdf_image_redactor.cpp`) call the loaders
    without it.
- **Pattern color spaces rejected for images (`bbb9926d4`):** ISO 32000-1 table 89 forbids them; an
  8 bpc image with one reached a `NOTREACHED()` in `CPDF_PatternCS::GetRGB()`, so a malformed file
  could crash rendering. The image now fails to load instead.
- **Renames (`7e01bafbd`):** `bTransMask` to `is_transparency_mask`; nothing of ours used the name.
- Merged into files we change: `cpdf_colorspace`, `cpdf_dib`, `cpdf_image`, `cpdf_imageloader`,
  `cpdf_pageimagecache`, `cpdf_renderstatus`, `fpdf_editimg.cpp`; all of upstream's hunks present.
