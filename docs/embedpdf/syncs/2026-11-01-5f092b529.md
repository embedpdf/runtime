## Upstream changes outside the conflicts

- **Embedder tests on display lists** (`efb720209`, `181518ea0`, `0f3d165be`, `57e9a2667`,
  `87bd48726`, `a5a0f99ff`). Our tests follow:
  - `EPDFViewEmbedderTest.EPDFDocSetPageRotationByObjectNumber` used upstream's deleted
    `rectangles_rotated` PNG; it compares the display list now, as upstream's own rotation test does.
  - `FPDFAnnotEmbedderTest.ExtractInkMultiple` and `SetFontColor` draw with our appearance
    generator (rule own-appearance-generator): round caps and joins and a stroke-fitted box for ink,
    a different first-line inset for free text. Their dumps are ours, written with
    `--write-results` and tagged in the tests; the rest of each display list matches upstream's.
- **Saved headers carry the major version (`d36b525a8`, test `17e04655e`):** a PDF 2.0 file saves as
  `%PDF-2.0`, no longer `%PDF-1.0`. Merged into our `cpdf_creator.cpp`.
- **Free xref entries (`7a364ab9b`):** upstream's new test records its xref with gaps, with a TODO
  (crbug.com/42271313) to remove them. Our complete xref (#86, rule complete-xref) already writes
  one subsection with the free entries linked, so the test expects ours.
- **Arabic `/ActualText` orderings (`64df52afe`):** a new test of four ways to write the same word.
  Upstream extracts one right; the fork none. With our `/ActualText` rules (bug-fix: a span is
  reversed only after literal right-to-left text, which keeps Acrobat's shaped runs right),
  variant 2's spans come out in visual order, where upstream reverses them. The test records the fork's results;
  ordering a line's spans by position would fix both. See Open questions.
- **Brotli compiled in by default (`5b8d8c787`).** `/BrotliDecode` streams decode only when start-up
  passes config version 6 with `m_BrotliEnabled`; our threads start through `EPDF_InitThread`
  without a config, so it would never run. Our release builds set `pdf_enable_brotli=false`
  (`build-target.sh`): the darwin-arm64 library is 167,968 bytes smaller (9,996,480 to 9,828,512),
  the wasm32 archive 189,292 bytes; exports unchanged. Test builds keep it, so its tests run, and
  its switch is per thread there (see Globals). Turning it on later: drop the argument and pass the
  config through `EPDF_InitThread`.
- **Scanline compositor vectorized (`4e36424cb`):** two Highway kernels with runtime dispatch, byte
  for byte the scalar result, and libyuv for the BGR24 to BGRx expand.
- **`CPDF_SyntaxParser::pool_` is used (`6876f741c`):** parsed names are interned. Our save reader
  still clears its pool between objects (save-traversal).
- **Near-axis rectangles (`8e5483c62`)**, see Likely security fixes; `ScopedLocale` moved to
  `core/fxcrt` (`ae6ae3ca9`); lcms 2.19.1 (`55ed4ec42`).
- Not in our builds: GDI+ removal (`2dbda71a1`), the `CGdiDisplayDriver` nit (`83adc17d6`), XFA
  (`f47593101`, `5f092b529`), PartitionAlloc for Skia builds (`320708bfb`; we set
  `pdf_use_partition_alloc=false`), the removed `pdf_skia_font_manager_target` (`4cd9288dd`; we
  never set it).

## Globals

`check-globals.py` on the darwin-arm64 release build found one: `g_brotli_enabled`, Brotli's
switch, written by `FPDF_InitLibraryWithConfig`. Library start-up runs on every thread (rule
per-thread-init), so a shared flag would be written by each thread's start-up, and a start-up
without a config would turn it off for all. It is `EPDF_TLS` now (thread-confined-globals); ok after
that (263 shared writable, 26 thread-local). Release builds now leave Brotli out (25 thread-local).
