## Upstream changes outside the conflicts

- **Kerning (`7183fe842`).** A text object no longer stores a TJ number as a separator item
  (`kInvalidCharCode` in `char_codes_`, the number in `char_positions_`): `char_kernings_[i]` is the
  number after glyph i, and `char_positions_` has one entry per glyph. Ported:
  - `CPDF_PageContentGenerator`'s TJ writer reads `GetCharKernings()` (text with no kerning still
    gets Tj);
  - `RedactTextObjectMulti()` walks glyphs only, adds `kernings[i]` to the gap after glyph i
    (`RedactionState::AddKerningAfterGlyph()`) and reads a glyph's position as `positions[i]`;
  - the Type3 redactor's code sets take every code (no separators to skip);
  - `CPDF_ParsedSize` counts the kerning array;
  - `CPDF_TextObject::GetSeparatorAdjustment()` deleted (no readers left).
- **Loose character box (`ff5e04acc`).** `GetLooseBounds()` uses the font's ascent and descent
  from the glyph's origin instead of `/FontBBox`. `GetCharLocalBoxes()` (rule text-geometry)
  follows, so `EPDFText_GetCharGeometry` and `FPDFText_GetLooseCharBox` still agree
  (`EPDFTextEmbedderTest.GetCharGeometry`). Loose boxes, which the engine's selection uses, get
  shorter for fonts with a tall `/FontBBox`.
- **Renames.** `CFX_Font::LoadFaceFromSpan()` → `LoadFaceZeroFromSpan()` (`4d753679f`; it copied
  the data before too), in the annotation font map, the font registry and a test.
  `CPDF_TextObject::CountChars()` → `CharCount()`.
- **HarfBuzz path (`fc346b1d1`).** `third_party/harfbuzz-ng` → `third_party/harfbuzz`: our deps in
  `core/fpdfdoc/BUILD.gn` and `core/fxge/BUILD.gn`, and the test font paths in the annotation and
  measure tests.
